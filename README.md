# 家庭点菜手账

一个纯前端的家庭点菜 / 菜单分享 PWA。记菜谱、随机点菜、把「今天吃什么」分享给家里人。

**没有后端、没有登录、没有外部 API、没有 CDN 依赖。** 所有代码、样式、图标、压缩算法都内联在一个 `index.html` 里，断网完全可用。

---

## 一分钟跑起来

```bash
npm install
npm run dev        # 开发，浏览器打开提示的地址
npm run build      # 产出 dist/index.html（单文件，约 375 KB）
npm test           # 跑 58 个自动化测试
npm run icons      # 重新生成图标（改了 scripts/make-icons.mjs 才需要跑）
```

`npm run build` 之后 `dist/` 长这样：

```
dist/
├── index.html            ← 整个应用都在这里面（JS/CSS/图标全部内联）
├── manifest.webmanifest  ← PWA 清单（托管时用，见下文）
├── sw.js                 ← Service Worker（托管时用，见下文）
└── icon-180.png / icon-512.png
```

**直接双击 `dist/index.html` 就能用**（`file://` 协议下完全正常）。想装到手机上就按下面任意一种方式托管。

> **在微信里打开请用「链接」而不是「文件」。** 微信 iOS 点开别人发来的 .html 文件时，
> 文档处于**不透明源**（custom scheme / 沙箱 WKWebView），WebKit 会拒绝执行 ES module 脚本；
> 而且分享链接功能本来就依赖一个真实的域名（`file://` 的链接发给别人打不开）。
> 托管起来发链接，才是这个应用被设计出来的用法。

## 卡在「正在翻开手账…」怎么办

启动失败时现在**会把原因直接显示在屏幕上**（红色标题「手账没能翻开」+ 错误详情 + 地址协议 / 运行环境 / IndexedDB 是否可用）。
截图发出来就能定位，不用再靠猜。

内置了两道保险：

- 全局 `error` / `unhandledrejection` 监听 —— 脚本抛错立刻显示
- 8 秒看门狗 —— 专门抓「脚本压根没执行」这种不触发任何错误事件的情况

历史上已经踩过的一个坑，写在这里给以后的自己看：

> 构建产物里内联的是 `<script type="module" crossorigin>`。在不透明源的文档里
> （微信打开的本地文件就是），WebKit 拒绝执行 module 脚本 —— HTML 渲染出来了，
> 但 JS 一行都不跑，永远停在开屏文案上。桌面浏览器上完全复现不出来。
>
> 修法：打包格式改成 **IIFE**（`vite.config.ts` 里的 `rollupOptions.output.format`），
> 变成一个普通 `<script>`，任何 WebView 都执行。单文件应用本来就没有 import/export 需要保留，
> 降级零成本。另外加了一个 `classicScript()` 插件兜底改标签，`tests/build.test.mjs`
> 用断言钉死「产物里不许再出现 type="module"」。

还有第二个坑，是上面这个修法**带出来的**：

> Vite 打包会把 `<script type="module">` 提升到 `<head>`。module 有 defer 语义，
> 放哪儿都行；但降级成普通脚本后 defer 就没了 —— 普通内联脚本在 `<head>` 里
> **立即同步执行**，那时 `<body>` 还没解析到，`getElementById('root')` 是 `null`，
> 应用挂在第一行。
>
> 最坑的是症状：这一步抛的错发生在诊断脚本注册 `window.onerror` **之前**，
> 一个字都捕获不到，屏幕上只剩 8 秒后那句「应用脚本似乎完全没有执行」。
> 排查时看到的是「脚本没跑」，真因却是「脚本跑了，第一行就炸了」。
>
> 修法两处：`relocateEntryScript()` 把入口脚本挪回 `</body>` 前面（恢复文档
> 原本的顺序，也保证诊断脚本仍在应用脚本之前）；`main.tsx` 里再加一道
> 「等 `DOMContentLoaded` 再挂载」，让它不依赖脚本位置。
>
> **教训**：光断言产物「长得对」（没有 module、没有外部引用、看门狗在）是不够的 ——
> 上面每一条都通过了，应用照样打不开。`tests/build.test.mjs` 里那条
> 「把产物真的跑起来」的测试，就是为此加的：在 jsdom 里执行整个 `dist/index.html`，
> 断言应用真的挂载上了。写产物断言的测试，别忘了也把产物跑一遍。

## 部署

### 方式一：GitHub Pages（推荐，一条命令）

首次要做的两件事：

1. 在 github.com 上建一个**空的公开仓库** —— 不要勾 README / .gitignore / license，
   否则第一次 push 会因为历史无关而冲突。
2. 把仓库地址配到本地：

   ```bash
   git remote add origin https://github.com/<你的用户名>/<仓库名>.git
   git push -u origin main          # 推源码
   ```

之后每次发布就一条命令：

```bash
npm run deploy
```

它会重新构建，把 `dist/` 的内容推成一个 **gh-pages 分支**（不经过 `main`，
源码历史里不会堆构建产物），并自动放一个 `.nojekyll`。

最后去仓库 **Settings → Pages**，把 Source 选成 `gh-pages` 分支。地址是
`https://<你的用户名>.github.io/<仓库名>/`。**这一步只需设置一次**，
以后 `npm run deploy` 会自动更新。

> 不需要额外配置 `base`：`vite.config.ts` 里已经设了 `base: './'`，
> 放在任意子路径下都能正确加载。

### 方式二：Vercel

```bash
npm i -g vercel
vercel            # 首次会问几个问题，全默认即可
vercel --prod     # 发布到正式地址
```

框架预设选 **Vite**，Build Command 保持 `npm run build`，Output Directory 填 `dist`。

### 方式三：任意静态托管

`npm run build` 之后把整个 `dist/` 目录上传上去就行（Netlify、对象存储、自己的服务器……）。
不需要任何服务端逻辑，也不需要配置路由重写 —— 分享链接用的是 query 参数，不是路径。

## 添加到主屏幕

### iPhone / iPad（Safari）

1. Safari 打开部署好的网址（**必须是 Safari**，微信内置浏览器不行）
2. 点底部的「分享」按钮 → 「添加到主屏幕」
3. 起个名字，点「添加」

从主屏幕图标打开就是**全屏无浏览器地址栏**的，刘海和底部横条的安全区已经适配过。

### Android（Chrome）

1. Chrome 打开网址
2. 右上角「⋮」→「添加到主屏幕」/「安装应用」
3. 确认

应用会自动注册 Service Worker，之后**断网也能打开**。

### 图标是怎么来的

`public/` 里那两张 PNG 不是手画的，是 `scripts/make-icons.mjs` 生成出来的：

```bash
npm run icons      # 重新生成 public/icon-180.png 和 public/icon-512.png
```

脚本用 Node 自带的 `zlib` 手写了一个 PNG 编码器，零依赖。图形按测量的参数重画
（碗沿椭圆、碗身轮廓、三缕热气的曲线、横线间距），**没有矢量源文件也能改配色改尺寸**。

两张图的分工：

| 文件 | 用途 | 说明 |
| --- | --- | --- |
| `icon-180.png` | `apple-touch-icon` + 清单里的 `any` | iPhone 主屏图标就用这张，1:1 还原设计稿 |
| `icon-512.png` | 清单里的 `maskable` | Android 主屏图标。`maskable` 要求内容落在画布中心**直径 80% 的安全区**内，因为各家会用不同形状去裁 |

> 之前踩过的坑：`icon-512.png` 一度就是 `icon-180.png` 的复制品（两个文件 md5 一模一样），
> 清单里却按 `512x512` + `maskable` 声明。Android 拿 180 的图当 512 用会发虚，
> 而且那张图是画满整张画布的，按圆形一裁碗沿就断了。**iOS 走的是 apple-touch-icon，
> 完全看不出问题** —— 所以这个 bug 在 iPhone 上永远发现不了。
> 现在 `tests/icons.test.mjs` 会用 PNG 头校验「声明的尺寸必须是真的」，
> 并逐个像素确认 maskable 的内容确实落在安全区内。

> **关于离线**：`file://` 直接打开时不会注册 Service Worker（浏览器不允许），
> 但应用本身不需要网络，所以照样能用。Service Worker 只在 http/https 托管时启用。

> **发版后要让人看到**：SW 对导航请求是**缓存优先**，所以 `sw.js` 里的缓存名
> 绑定了 `index.html` 的内容哈希（构建时由 `stampServiceWorker()` 写入）。
> 内容一变 → `sw.js` 字节跟着变 → 浏览器重装 SW → `activate` 删掉旧缓存。
> 缓存名如果写死（原来是 `family-menu-v1`），`sw.js` 永远不会变，
> **装过应用的人就再也收不到新版本**，发多少次版都一样。
> `tests/build.test.mjs` 会校验这个哈希和当前产物是一致的。

## 功能

界面上是三个页签 + 一个页脚：

| 位置 | 能干什么 |
| --- | --- |
| **📖 菜谱本** | 记菜谱（名字/分类/难度/食材/备注/照片），分类筛选、按菜名或食材搜索。长按卡片直接编辑，卡片「···」可以换图、复制一份、删除（删除有 10 秒撤销）。多选模式下能批量删除、批量改分类。 |
| **🍽️ 今日菜单** | 勾选菜谱组成今天的菜单，可以往前/往后翻日期看往日菜单。选好了「分享这份菜单」。 |
| **🎲 抽签点菜** | 一个大大的「今天吃啥？」按钮，转盘式抽菜（0.8 秒）。可以勾上「只在当前筛选分类里抽」。抽中可以「加入今日菜单」或「再来一次」。 |
| **⚙️ 设置**（页脚） | 导出/导入 JSON 备份（含图片），看本地存储占用情况，重新载入预置菜谱，清空所有数据。 |

标签栏在手机上是贴底的固定栏，在宽屏上变成封面下面的一排书签。
设置是页脚按钮打开的全屏浮层，不是第四个页签。

### 分享链接是怎么工作的

「分享这份菜单」会生成一个形如 `https://你的域名/?m=XXXXX` 的链接，**只有菜名、分类、emoji 三样东西**：

- 用 lz-string 压缩后拼进 query 参数（源码已内联进 `src/lib/lz-string.ts`，不走 CDN）
- 走系统分享面板（`navigator.share`），不支持就退回复制到剪贴板
- 对方打开链接会直接进只读预览页，可以「存到我的今日菜单」或「全部加入我的菜谱库」
- 同名菜会自动关联到你已有的菜谱，不会重复建

**链接里为什么不带图片？** base64 图片动辄几十 KB，拼进 URL 后长度会爆掉，微信/QQ 会直接截断导致链接打不开。所以对方的预览页里图片位置用 emoji 兜底。图片请用「导出/导入 JSON」跨设备搬。

链接超过 1800 字符时会提示你精简菜单（这个长度是保守估计的安全线，实测十几道菜的普通家宴只有几百字符，离得很远）。

### 跨设备搬数据

设置页 → **导出菜谱库** → 得到一个 JSON 文件（图片已转成 base64 一起打包，所以文件可能有好几 MB）。
在另一台设备上 → **导入菜谱库** → 选这个文件。

导入按 id 去重合并：**已存在的菜谱不会被覆盖**（本地那份是你正在用的，被旧备份悄悄改掉最难排查）。

## 数据存在哪

- **菜谱和图片** → IndexedDB（图片以 Blob 形式存，不占 localStorage 的 5MB 配额）
- **设置项** → localStorage

数据只在这台设备的这个浏览器里，不会上传到任何地方。

**隐私模式 / IndexedDB 不可用时会自动降级**：先退到 localStorage，再退到纯内存（用完即丢），并在界面上给出提示，不会白屏。

## 实现要点

```
src/
├── types.ts              数据模型、分类、难度、emoji 池
├── lib/
│   ├── lz-string.ts      内联的 lz-string 1.5.0（原版源码，未改动算法）
│   ├── share.ts          分享链接编解码（含超长/坏链接的兜底）
│   ├── image.ts          canvas 压缩：最长边 800px、质量 0.75、EXIF 方向校正
│   ├── backup.ts         导出/导入 JSON
│   ├── date.ts           本地时区日期（刻意避开 toISOString 的 UTC 坑）
│   ├── io.ts             下载/选文件/复制/系统分享
│   └── nanoid.ts         轻量 id 生成
├── db/
│   ├── storage.ts        IndexedDB → localStorage → 内存 三级降级
│   └── seed.ts           12 道预置菜 + 「只播种一次」标记
├── store/                模块级 store（useSyncExternalStore），非 Context
├── hooks/                visualViewport / 返回键拦截 / 中文输入法 / 长按
├── components/           封面、卡片、胶带、便签、标签栏、页脚、Toast、确认框、编辑器
├── pages/                菜谱库 / 点菜 / 今日菜单 / 设置 / 分享预览
└── styles/global.css     手账风设计系统

scripts/
├── make-icons.mjs        生成 PWA 图标（自带 PNG 编码器）
└── deploy.mjs            发布到 GitHub Pages
```

几个值得一提的地方：

- **预置菜只播种一次**：判断依据是「数据库是否为空」**加上** localStorage 里的 `seeded` 标记。
  只有前者的话，用户把预置菜全删了下次打开又会全冒出来；播种进去之后它们就是普通数据，改名换图都不会被覆盖。
- **中文输入法回车**：监听 `compositionstart` / `compositionend`，并额外用 `isComposing`、
  `keyCode === 229` 和 `compositionend` 后 60ms 的宽限窗口三重兜底。否则用拼音打食材时，
  还没选字的回车就会被当成「确认添加」，输入框里蹦出半截拼音。
- **编辑器草稿**：锁屏、切后台、误按返回键都会把未保存的改动存进 sessionStorage，
  下次打开时恢复并提示「已恢复未保存的修改」。返回键会先问一句「放弃修改？」而不是默默关掉。
- **键盘不挡输入框**：全屏编辑弹层用 `visualViewport` API 动态算高度，输入框获得焦点后
  自动滚动到可见区域。
- **iOS 不会自动放大**：所有输入框 `font-size: 16px`（低于 16px 时 iOS 会自动缩放页面，很烦）。
- **手账外观全靠 CSS**：米黄横线纸底、左侧红色装订线、手绘不规则圆角
  （`--r-card` 那串长短相间的 border-radius）、胶带和便签的倾斜，都是 CSS 做的，
  没有一张背景图。字体走系统兜底（标题行楷、正文楷体），**不引网络字体**。
  每个分类有自己的配色，卡片胶带的颜色跟着分类走。
- **`<input type="file">` 绝对不能待在 `BottomSheet` 里**：弹层是 `if (!open) return null`，
  而「从相册选」是先 `input.click()` 再关弹层 —— 系统选择器刚弹出来，承载它的 input 就被
  React 卸载了。原生 `change` 事件对游离节点照样触发（在 input 上直接 `addEventListener`
  收得到），但 React 17+ 把事件委托挂在**根容器**上，脱离文档的节点冒泡不到那儿，
  `onChange` 一次都不跑。表现就是「选完照片什么也没发生」。两个换图入口都踩了这个坑，
  现在统一把 input 提到弹层外面常驻；`tests/render.test.mjs` 里除了断言这个，
  还钉了一条通用规则：**任何 file input 都不许 `el.closest('.sheet')`**。
  设置页的「导入」一直没事，因为它走 `lib/io.ts` 的 `pickFile`——自己 `addEventListener`、
  用完才摘节点，对照着看就知道差别在哪。
- **关弹层会顺手清掉父组件传下来的 id**：`ChangeImageSheet` 的 `recipeId` 是
  `imageForId ?? ''`，一关弹层就变空字符串，React 还会把 `onChange` 换成新那次渲染的闭包。
  可 `change` 要等用户选完图才到，那时 `patchRecipe('')` 找不到菜谱、返回 `false`，**静默失败**。
  所以组件把「这次是给哪道菜换图」冻在打开弹层那一刻（`targetId` ref），不读实时 prop。
  修完第一个坑才轮到它 —— 两个坑的症状一模一样，都是「选完图没反应」。
- **`--fixed-bottom` 这个变量别绕过**：手机端标签栏是 `position: fixed` 贴底的，
  页面留白、多选栏、Toast 三处都要避开它；宽屏上标签栏回到文档流，这三处就得同时归零。
  所以它们统一读 `--fixed-bottom`，改的时候只改 `:root` 里那一个值。
- **PWA 清单和图标构建时内联**：单文件模式（`file://` 双击打开）取不到旁边的
  `manifest.webmanifest` 和 png，所以这两样必须写成 `data:` URI。但手写 base64
  意味着同一份图标有两份副本，改了 `public/` 里的图、内联的那份不会跟着变 ——
  之前的 180/512 混乱就是这么攒出来的。现在 `vite.config.ts` 里的
  `inlinePwaAssets()` 在构建时从 `public/manifest.webmanifest` 派生内联版本，
  **清单只维护一份**。托管时启动脚本再换回真实文件路径，Service Worker 才能正常工作。

## 验收清单

派上用场的话可以照着走一遍：

**基本**
- [ ] 第一次打开没有报错，能看到 12 道预置菜
- [ ] 刷新页面，改动还在
- [ ] 改掉某道预置菜的名字，重启应用，改动还在（没有被预置数据覆盖）

**编辑**
- [ ] 所有输入框聚焦时页面**不会**被放大（iOS）
- [ ] 键盘弹起时正在编辑的输入框仍然可见
- [ ] 用拼音输入食材，选字前的回车**不会**添加食材
- [ ] 编辑到一半锁屏 / 切后台，回来能看到「已恢复未保存的修改」
- [ ] 点选一张 10MB 以上的照片，压缩过程不卡死
- [ ] 卡片「···」→ 换图 → 选一张照片，**卡片上真的出现了图片**（不是「选完没反应」）
- [ ] 编辑页点大图区域 → 从相册选，同样能换上
- [ ] 删除菜谱 → 提示里有「撤销」，10 秒内点撤销能恢复

**分享**
- [ ] 分享链接里**不含** `+` 和 `/`（微信/QQ 会转义这两个字符）
- [ ] 微信里打开分享链接，能进预览页
- [ ] 点「存到我的今日菜单」，今日菜单里出现这些菜
- [ ] 菜名和已有菜谱重复时，不会建出重复的菜谱

**移动端**
- [ ] iPhone 添加到主屏幕后是全屏的，刘海和底部横条不挡内容
- [ ] Android 返回键在编辑页会先问「放弃修改？」

产物内容走，跑之前需要先 `npm run build`）。

`tests/render.test.mjs` 会在 jsdom 里把整个 App 真的挂载一遍，断言外壳结构
（封面 / 标签栏 / 纸面 / 页脚 / 三个页签）和卡片的胶带、分类标签、难度星星都在。
加这个文件的直接原因是：换皮时新封面本来叫 `.cover`，而编辑器的大图区域早就占了
这个类名 —— 两个 CSS 规则互相覆盖，`tsc` 和 `npm run build` 都不会报错，
只有把页面渲染出来才发现。

它后来还接了一个「换图」的用例，断言的是**弹层关掉之后，选图的 input 还在不在文档里**，
并且真的派发一次 `change`，确认图最终落到了卡片上。这类 bug 之所以能藏那么久，
是因为每一条静态断言都是通过的：`tsc` 干净、构建成功、标记、类名、`onChange` 也确实挂上了 ——
**唯一的错处是那个 input 已经不在 document 里了**，而这是只有把页面跑起来、真的点一遍才看得见的。
和上面「产物长得对 ≠ 产物能跑」是同一类教训。

> 喂一个 jsdom 的 `File` 进去直接 `ERR_INVALID_ARG_TYPE`。
