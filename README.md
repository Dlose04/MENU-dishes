# 家庭点菜手账

一个纯前端的家庭点菜 / 菜单分享 PWA。记菜谱、随机点菜、把「今天吃什么」分享给家里人。

**没有后端、没有登录、没有外部 API、没有 CDN 依赖。** 所有代码、样式、图标、压缩算法都内联在一个 `index.html` 里，断网完全可用。

---

## 一分钟跑起来

```bash
npm install
npm run dev        # 开发，浏览器打开提示的地址
npm run build      # 产出 dist/index.html（单文件，约 325 KB）
npm test           # 跑 43 个自动化测试
```

`npm run build` 之后 `dist/` 长这样：

```
dist/
├── index.html            ← 整个应用都在这里面（JS/CSS/图标全部内联）
├── manifest.webmanifest  ← PWA 清单（托管时用，见下文）
├── sw.js                 ← Service Worker（托管时用，见下文）
└── icon-180.png / icon-512.png
```

**直接双击 `dist/index.html` 就能用**（`file://` 协议下完全正常）。想装到手机上就按下面任意一种方式托管。

> **在微信里打开请用「链接」而不是「文件」。** 微信 iOS 点开别人发来的 .html 文件时，
> 文档处于**不透明源**（custom scheme / 沙箱 WKWebView），WebKit 会拒绝执行 ES module 脚本；
> 而且分享链接功能本来就依赖一个真实的域名（`file://` 的链接发给别人打不开）。
> 托管起来发链接，才是这个应用被设计出来的用法。

## 卡在「正在翻开手账…」怎么办

启动失败时现在**会把原因直接显示在屏幕上**（红色标题「手账没能翻开」+ 错误详情 + 地址协议 / 运行环境 / IndexedDB 是否可用）。
截图发出来就能定位，不用再靠猜。

内置了两道保险：

- 全局 `error` / `unhandledrejection` 监听 —— 脚本抛错立刻显示
- 8 秒看门狗 —— 专门抓「脚本压根没执行」这种不触发任何错误事件的情况

历史上已经踩过的一个坑，写在这里给以后的自己看：

> 构建产物里内联的是 `<script type="module" crossorigin>`。在不透明源的文档里
> （微信打开的本地文件就是），WebKit 拒绝执行 module 脚本 —— HTML 渲染出来了，
> 但 JS 一行都不跑，永远停在开屏文案上。桌面浏览器上完全复现不出来。
>
> 修法：打包格式改成 **IIFE**（`vite.config.ts` 里的 `rollupOptions.output.format`），
> 变成一个普通 `<script>`，任何 WebView 都执行。单文件应用本来就没有 import/export 需要保留，
> 降级零成本。另外加了一个 `classicScript()` 插件兜底改标签，`tests/build.test.mjs`
> 用断言钉死「产物里不许再出现 type="module"」。

## 部署

### 方式一：GitHub Pages

```bash
npm run build
cd dist
git init && git add -A && git commit -m "deploy"
git branch -M gh-pages
git remote add origin git@github.com:<你的用户名>/<仓库名>.git
git push -f origin gh-pages
```

然后在仓库 **Settings → Pages** 里把 Source 选成 `gh-pages` 分支，地址是
`https://<你的用户名>.github.io/<仓库名>/`。

> 这里用的是「把 dist 目录单独推成一个 gh-pages 分支」的做法，不需要额外配置 `base`，
> 因为 `vite.config.ts` 里已经设了 `base: './'`，放在任意子路径下都能正确加载。

### 方式二：Vercel

```bash
npm i -g vercel
vercel            # 首次会问几个问题，全默认即可
vercel --prod     # 发布到正式地址
```

框架预设选 **Vite**，Build Command 保持 `npm run build`，Output Directory 填 `dist`。

### 方式三：任意静态托管

`npm run build` 之后把整个 `dist/` 目录上传上去就行（Netlify、对象存储、自己的服务器……）。
不需要任何服务端逻辑，也不需要配置路由重写 —— 分享链接用的是 query 参数，不是路径。

## 添加到主屏幕

### iPhone / iPad（Safari）

1. Safari 打开部署好的网址（**必须是 Safari**，微信内置浏览器不行）
2. 点底部的「分享」按钮 → 「添加到主屏幕」
3. 起个名字，点「添加」

从主屏幕图标打开就是**全屏无浏览器地址栏**的，刘海和底部横条的安全区已经适配过。

### Android（Chrome）

1. Chrome 打开网址
2. 右上角「⋮」→「添加到主屏幕」/「安装应用」
3. 确认

应用会自动注册 Service Worker，之后**断网也能打开**。

> **关于离线**：`file://` 直接打开时不会注册 Service Worker（浏览器不允许），
> 但应用本身不需要网络，所以照样能用。Service Worker 只在 http/https 托管时启用。

## 功能

| 页面 | 能干什么 |
| --- | --- |
| **菜谱库** | 记菜谱（名字/分类/难度/食材/备注/照片），分类筛选、按菜名或食材搜索。长按卡片直接编辑，卡片「···」可以换图、复制一份、删除（删除有 10 秒撤销）。多选模式下能批量删除、批量改分类。 |
| **点菜** | 一个大大的「今天吃啥？」按钮，转盘式抽菜（0.8 秒）。可以勾上「只在当前筛选分类里抽」。抽中可以「加入今日菜单」或「再来一次」。 |
| **今日菜单** | 勾选菜谱组成今天的菜单，可以往前/往后翻日期看往日菜单。选好了「分享这份菜单」。 |
| **设置** | 导出/导入 JSON 备份（含图片），看本地存储占用情况，重新载入预置菜谱，清空所有数据。 |

### 分享链接是怎么工作的

「分享这份菜单」会生成一个形如 `https://你的域名/?m=XXXXX` 的链接，**只有菜名、分类、emoji 三样东西**：

- 用 lz-string 压缩后拼进 query 参数（源码已内联进 `src/lib/lz-string.ts`，不走 CDN）
- 走系统分享面板（`navigator.share`），不支持就退回复制到剪贴板
- 对方打开链接会直接进只读预览页，可以「存到我的今日菜单」或「全部加入我的菜谱库」
- 同名菜会自动关联到你已有的菜谱，不会重复建

**链接里为什么不带图片？** base64 图片动辄几十 KB，拼进 URL 后长度会爆掉，微信/QQ 会直接截断导致链接打不开。所以对方的预览页里图片位置用 emoji 兜底。图片请用「导出/导入 JSON」跨设备搬。

链接超过 1800 字符时会提示你精简菜单（这个长度是保守估计的安全线，实测十几道菜的普通家宴只有几百字符，离得很远）。

### 跨设备搬数据

设置页 → **导出菜谱库** → 得到一个 JSON 文件（图片已转成 base64 一起打包，所以文件可能有好几 MB）。
在另一台设备上 → **导入菜谱库** → 选这个文件。

导入按 id 去重合并：**已存在的菜谱不会被覆盖**（本地那份是你正在用的，被旧备份悄悄改掉最难排查）。

## 数据存在哪

- **菜谱和图片** → IndexedDB（图片以 Blob 形式存，不占 localStorage 的 5MB 配额）
- **设置项** → localStorage

数据只在这台设备的这个浏览器里，不会上传到任何地方。

**隐私模式 / IndexedDB 不可用时会自动降级**：先退到 localStorage，再退到纯内存（用完即丢），并在界面上给出提示，不会白屏。

## 实现要点

```
src/
├── types.ts              数据模型、分类、难度、emoji 池
├── lib/
│   ├── lz-string.ts      内联的 lz-string 1.5.0（原版源码，未改动算法）
│   ├── share.ts          分享链接编解码（含超长/坏链接的兜底）
│   ├── image.ts          canvas 压缩：最长边 800px、质量 0.75、EXIF 方向校正
│   ├── backup.ts         导出/导入 JSON
│   ├── date.ts           本地时区日期（刻意避开 toISOString 的 UTC 坑）
│   ├── io.ts             下载/选文件/复制/系统分享
│   └── nanoid.ts         轻量 id 生成
├── db/
│   ├── storage.ts        IndexedDB → localStorage → 内存 三级降级
│   └── seed.ts           12 道预置菜 + 「只播种一次」标记
├── store/                模块级 store（useSyncExternalStore），非 Context
├── hooks/                visualViewport / 返回键拦截 / 中文输入法 / 长按
├── components/           卡片、胶带、便签、底部 Tab、Toast、确认框、编辑器
├── pages/                菜谱库 / 点菜 / 今日菜单 / 设置 / 分享预览
└── styles/global.css     手账风设计系统
```

几个值得一提的地方：

- **预置菜只播种一次**：判断依据是「数据库是否为空」**加上** localStorage 里的 `seeded` 标记。
  只有前者的话，用户把预置菜全删了下次打开又会全冒出来；播种进去之后它们就是普通数据，改名换图都不会被覆盖。
- **中文输入法回车**：监听 `compositionstart` / `compositionend`，并额外用 `isComposing`、
  `keyCode === 229` 和 `compositionend` 后 60ms 的宽限窗口三重兜底。否则用拼音打食材时，
  还没选字的回车就会被当成「确认添加」，输入框里蹦出半截拼音。
- **编辑器草稿**：锁屏、切后台、误按返回键都会把未保存的改动存进 sessionStorage，
  下次打开时恢复并提示「已恢复未保存的修改」。返回键会先问一句「放弃修改？」而不是默默关掉。
- **键盘不挡输入框**：全屏编辑弹层用 `visualViewport` API 动态算高度，输入框获得焦点后
  自动滚动到可见区域。
- **iOS 不会自动放大**：所有输入框 `font-size: 16px`（低于 16px 时 iOS 会自动缩放页面，很烦）。

## 验收清单

派上用场的话可以照着走一遍：

**基本**
- [ ] 第一次打开没有报错，能看到 12 道预置菜
- [ ] 刷新页面，改动还在
- [ ] 改掉某道预置菜的名字，重启应用，改动还在（没有被预置数据覆盖）

**编辑**
- [ ] 所有输入框聚焦时页面**不会**被放大（iOS）
- [ ] 键盘弹起时正在编辑的输入框仍然可见
- [ ] 用拼音输入食材，选字前的回车**不会**添加食材
- [ ] 编辑到一半锁屏 / 切后台，回来能看到「已恢复未保存的修改」
- [ ] 点选一张 10MB 以上的照片，压缩过程不卡死
- [ ] 删除菜谱 → 提示里有「撤销」，10 秒内点撤销能恢复

**分享**
- [ ] 分享链接里**不含** `+` 和 `/`（微信/QQ 会转义这两个字符）
- [ ] 微信里打开分享链接，能进预览页
- [ ] 点「存到我的今日菜单」，今日菜单里出现这些菜
- [ ] 菜名和已有菜谱重复时，不会建出重复的菜谱

**移动端**
- [ ] iPhone 添加到主屏幕后是全屏的，刘海和底部横条不挡内容
- [ ] Android 返回键在编辑页会先问「放弃修改？」
- [ ] 隐私模式下打开有降级提示，但可以正常记菜谱

**自动化**

```bash
npm test      # 47 个测试
```

覆盖：分享链接编解码（含与官方 lz-string 逐字节对拍、坏链接不抛异常、超长提示可达）、
日期时区边界（跨月/跨年/闰年）、预置数据与播种规则、导出导入往返，
以及构建产物的断言（不许出现 module 脚本和外部资源引用，跑之前需要先 `npm run build`）。
